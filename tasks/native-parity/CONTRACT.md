# Exact native parity contract

The owner-selected current web board is the visual/interaction target. This
contract applies to every NP task; it is not a new design proposal. Ungenerated's
review/native-port/motion/accessibility/visual-QA checks inform the gates below.
The canonical product/data-safety boundaries continue to override generic recipes.

## What matching means

Use the current rendered composition and loaded override layers, not just the
old `barklog.js` or generated Kotlin token file. Inspect computed dimensions,
colour, font family/weight/size/line height, radius, padding, artwork, icons,
baseline and control poses. Match all nine typed editors and all named states.
Generic Material rows/fields are not equivalent to the board's considered parts.

Bricolage Grotesque 700/800 is the display/number family; Inter 400/500 is the
reading family, as explicitly selected by the owner on 2026-10-16. Bundle the
licensed fonts in both native hosts. No decorative shadows or gradients. Colour
never replaces labels/icons/values. Minimum interactive target is 48 dp.

Preserve actual data-driven behavior: notes/context, dog/date scopes, explicit
currency/units, drafts, SQL paging and native adapters. Translate example data to
real records, not hardcoded production totals. Do not copy demonstration export
percentages, fake health scores or simulated permission/share sheets into runtime.

## Safe, matched evidence

Use a dedicated, owned disposable QA environment, real SQLite/repositories and
explicit synthetic local records/photos. Never reset/uninstall a user's journal
to get a clean screenshot. Control time/date/timezone and use the same dog,
records, selection, keyboard/scroll state and locale on board and native.
Practice remains outside the journal. Fault/delay injection is explicit Debug
test infrastructure only, not a fake production repository or Release route.

Canonical phone: 390 × 844 logical pixels. Also review 375 × 667, 430 × 932 and
130% text in both themes, with final-state reduced motion. Compare app content
rectangles after documenting genuine OS safe-area/status/navigation-bar bounds;
do not squeeze native into a bitmap, draw a fake Dynamic Island or globally
rescale text to disguise mismatches. Responsive layouts may scroll/reflow; record
and review any necessary adaptation. No colour-only meaning, clipped keyboard
actions, hidden focus or inaccessible validation. Check screen-reader labels and
order; physical VoiceOver/TalkBack remain unproved until tested.

Each matched product/kit/motion/current-flow entry needs an evidence JSON path in
the manifest, with fixture ID, baseline identity/fingerprint, source revision/fingerprint,
board/iOS/Android captures and a reviewed visual comparison. Include rest light
and dark, compact and wide phone, 130% text, reduced motion and interaction
results. Do not substitute a family contact sheet for all child-state evidence.
Raster anti-aliasing may differ; geometry/type/colour/art differences need fixes
or explicit owner-approved exceptions, never a generous unexplained diff limit.
Paths should remain available to a reviewer; ignored local screenshots need a
durable handoff location before a completion claim survives cleanup.

## Motion parity

Read actual board clocks/curves/springs and the live current pose. Firm control
press is 0.97 scale/1 px/90 ms with 0.30 response, 0.86 damping release. Preserve
the current touch bubbles, appropriate sticker follow-through, number rolls,
dog entries/reactions and calm content entrances. Nothing celebrates a failed,
cancelled or uncommitted write. Early Undo and dog switching cannot replay rewards.

Implement push/cover/carry/Back by intent, correct outgoing layers, tab pill and
shared-object geometry, rather than one generic incoming rise. Keep one active
controller/editor; outgoing read-only presentation or a snapshot layer can
animate without a second autosaving editor. Back uncovers existing content without
replaying its entrance. Interrupt/re-tap from the current pose without jumps.

Capture real-time rest plus 25/50/75% motion frames for every transition, compare
forward and Back, and inspect 1×/0.5×/0.25× playback. No seek-and-guess captures.
Reduced motion lands on final poses immediately with written success, clear
pressed/focus states and stable logical focus. Native haptics/frame pacing remain
separate physical-device gates; web timing alone does not prove them.

## Contextual states and platform ownership

An inventory ID is a composition/behavior requirement, not necessarily a new
navigation route. Errors/permission states stay scoped to the operation; unknown
toxicity is not an online error, picker cancellation is not denial, and missing
photos retain metadata. Tasks save before/independently of reminder permission.
Offline logging/reading/Safety/export remain available without a new blocking page.

System photo/permission/share/print/call surfaces belong to the operating system.
Match BarkLog's pre/post-handoff screens and use real adapters; document OS visual
differences instead of building fake replicas. Historical references and feel
comparisons remain on the board/Debug; don't ship retired layouts or demo controls
as compulsory product destinations. The reduced-motion demo specifies global
behavior, not a mandatory screen.

## Status and closure

`open` → `in-progress` → `ready-for-review` → `matched` only after evidence and
individual owner approval. `reference-retained` is only for historical references.
The manifest is the machine-readable status authority; update each child task and
index with it. Do not edit only a Markdown checkbox to bypass the evidence gate.

For `matched`, evidence JSON must contain `baselineBoardId`, `baselineFingerprint`, `fixtureId`,
`sourceFingerprint`, a `board` capture path, `ios`/`android` objects with capture
paths and all `checks` true: `light`, `dark`, `compact`, `wide`, `text130`,
`reducedMotion`, `keyboardFocus`, `targets48`, `labelsOrder`, `contrast`,
`interaction`, `restComparison`, `motionFrames`, `slowPlayback`, `noSlop`.
`visualReview` identifies reviewer/date and unresolved differences (empty unless
each is separately owner-approved). `ownerApproval` records the owner's explicit
screen-specific approval (`scope` equals the board ID) and date; no invented Picks. Evidence is a necessary
gate, not an automatic machine claim of visual equality.
