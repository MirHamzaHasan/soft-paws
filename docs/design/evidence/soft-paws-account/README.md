Configured availability comes from the actual native engine, rather than an
integration-enabled flag. An unconfigured engine never receives credentials.
Create/reset routes remain distinct; legacy email links still map correctly.
Passwords and confirmation are transient and clear on background or route change.
Protected fields expose Empty/Entered. Reset instructions require native success;
unavailable requests never claim an email was sent. Local-care exits retain drafts.

Plans show every complete recurring charge and begin without a selection. Store
offers are authoritative when configured; otherwise the approved USD proposals
are labelled and purchase/restore are unavailable. Membership never invents an
entitlement or renewal date. Debug Premium preview is explicit, can be ended and
is absent in Release. Store cancellation remains a platform action. Terms/Privacy
are clearly labelled setup notes. Training/scanning are unavailable future ideas,
outside the active Premium benefits.

Android passes its normal screen/access cases and a separate protected-password
case with identical production sources, then all three cases at a cold 130%
launch. The password test follows the real Compose accessibility tree: the label
is a child of the editable native node. It waits for the same Activity to actually
stop before resuming; a fixed Home delay could finish before the transition.
Earlier locator/timing failures are excluded from accepted runtime claims.
